# 一、总体脉络

设备控制里的编程，不只是写普通业务逻辑。它更像是在软件和硬件之间搭桥。

上层应用里，程序主要处理数据、界面、网络和业务规则。设备端程序则更贴近硬件：它要读传感器、控制引脚、配置寄存器、处理中断、输出 PWM、进行串口通信，还要考虑时钟、电源、存储、看门狗和实时性。

这份内容分成两条主线：

1. C 语言：学习设备端编程的基础语言能力。
2. STM32：学习如何在单片机上用 C 语言控制真实硬件。

C 语言负责把底层能力讲清楚。它包括编译流程、类型系统、指针、数组、动态内存、结构体、函数指针、位运算、宏、编译链接和嵌入式接口。

STM32 负责把这些能力落到设备上。它包括开发环境、工程结构、GPIO、OLED、外部中断、定时器、ADC、DMA、USART、I2C、SPI、RTC、电源控制、看门狗和 Flash。

如果把设备看成一个系统，C 语言像是“写控制逻辑和驱动代码的工具”，STM32 像是“承载控制逻辑的硬件平台”。二者合在一起，才能完成一个完整的嵌入式控制项目。

# 二、C 语言部分

C 语言在设备控制方向上的作用，主要有三点：

1. 写驱动：直接操作寄存器、引脚、总线和外设。
2. 写业务主程序：把多个传感器、执行器和通信模块组合起来。
3. 理解嵌入式系统：理解内存、编译、链接、指针、位操作和硬件接口。

在设备端，C 语言不是“可选语言”，而是很多微控制器开发的默认语言。原因很简单：它足够贴近硬件，运行开销低，编译后能直接控制内存和寄存器。

## 1. 编译流程：代码怎样变成设备能执行的程序

C 程序不是像脚本一样直接运行。它要经过一条完整的构建链路：

```text
.c 源文件 -> 预处理 -> 编译 -> 汇编 -> 链接 -> 可执行文件/固件
```

预处理阶段会处理 `#include`、`#define`、条件编译等内容。头文件会被展开，宏会被替换，最终得到更完整的 C 源代码。

编译阶段会把 C 代码翻译成汇编代码。这个阶段会检查语法、类型、函数声明等问题。

汇编阶段会把汇编代码变成机器码，通常生成 `.o` 目标文件。

链接阶段会把多个目标文件和库文件合在一起，解决函数和变量之间的引用关系，最终生成可执行文件。在嵌入式里，最终产物往往会被下载到单片机 Flash 中。

这一章的意义是让人知道：C 程序不是一个孤立文件。一个嵌入式工程通常由启动文件、系统文件、外设库、用户代码、头文件和链接配置共同组成。

## 2. 类型系统：提前决定数据怎么放进内存

C 语言的变量不是随便变化的标签，而是固定类型、固定大小的内存区域。

比如 `int` 通常占 4 字节，`char` 占 1 字节，`float` 占 4 字节，`double` 占 8 字节。具体大小和平台有关，所以需要用 `sizeof` 来确认。

在设备控制中，类型大小非常重要。传感器数据、寄存器字段、通信协议数据包，往往都要求明确的字节长度。如果类型用错，可能导致数据解析错误，甚至控制行为异常。

`signed` 和 `unsigned` 用来决定整数是否有符号。无符号数常用于寄存器、位标志、计数器和数据包字节，因为它们本质上是二进制位，不一定表示正负。

`const` 表示变量不应该被修改。它可以用于保护配置参数、只读表、函数输入等。

`volatile` 在嵌入式里尤其重要。它告诉编译器：这个变量的值可能被外部因素改变，不要自作聪明地优化掉读取动作。硬件寄存器、中断中修改的变量、某些共享状态，常常需要 `volatile`。

## 3. 指针：C 语言连接内存和硬件的核心

指针是 C 语言的分水岭。

指针本质上是保存地址的变量。普通变量保存值，指针保存这个值所在的内存地址。通过 `&` 可以取地址，通过 `*` 可以解引用，也就是访问地址指向的内容。

设备控制为什么离不开指针？因为硬件寄存器本质上就是某个固定地址上的一段内存。要控制外设，就要向这些地址读写特定位。寄存器操作、数组传参、字符串处理、动态内存、驱动函数接口，都离不开指针。

函数参数在 C 里默认是值传递。函数拿到的是一份拷贝。如果想让函数修改外部变量，就要把变量地址传进去。

比如驱动函数常常写成：

```c
void Sensor_Read(SensorData *data);
```

这里传入的是结构体指针，函数可以把读取结果写回调用者提供的结构体里。

指针也会带来风险。野指针、空指针、悬垂指针、越界访问都会让程序崩溃或产生难以定位的问题。嵌入式程序没有复杂操作系统保护时，这些错误更危险。

## 4. 数组和字符串：连续内存的使用方式

C 的数组是一段连续内存。数组里每个元素类型相同，元素按顺序紧挨着排列。

数组名在很多场景下会退化成指向首元素的指针。这让数组传参变得高效，但也带来一个问题：函数里通常不知道数组长度，需要额外传入长度。

设备控制中经常用数组保存：

- 传感器采样数据
- 串口接收缓冲区
- I2C/SPI 发送缓冲区
- 滤波窗口
- 波形表
- OLED 显示缓存

C 字符串本质上是以 `\0` 结尾的字符数组。字符串处理必须注意结尾标记和缓冲区长度，否则容易越界。

在串口文本通信里，字符串很常见。比如单片机向电脑发送调试信息，或者接收一条文本命令，都需要处理字符数组和结束符。

## 5. 动态内存：手动申请和释放内存

C 语言可以用 `malloc`、`calloc`、`realloc` 和 `free` 管理堆内存。

动态内存的好处是灵活。程序可以在运行时根据需要申请不同大小的内存。

但在嵌入式开发中，动态内存要谨慎使用。原因是单片机内存有限，长期运行时容易出现内存泄漏、碎片化或分配失败。

设备控制程序通常更偏好静态分配。比如提前定义好缓冲区、结构体和任务状态，让内存布局稳定可控。

理解堆和栈也很关键。

栈通常用于局部变量和函数调用，速度快，但空间有限。

堆用于动态分配，灵活但需要手动管理。

全局变量和静态变量通常放在静态存储区，生命周期贯穿整个程序。

这些知识帮助我们判断一个变量该放在哪里，避免栈溢出、内存泄漏和不可预测的运行问题。

## 6. 结构体：把多个数据组织成一个设备对象

结构体用于把多个相关字段打包在一起。

在设备控制中，结构体非常自然。一个传感器可以有状态、配置、测量值、错误码；一个电机可以有速度、方向、PWM 占空比、编码器计数；一个通信包可以有包头、长度、命令、数据和校验。

比如：

```c
typedef struct {
    float temperature;
    float humidity;
    uint8_t status;
} SensorData;
```

`typedef` 可以简化结构体类型的写法，让代码更像在描述业务对象。

结构体还有内存对齐问题。编译器为了让 CPU 更高效访问数据，可能在字段之间插入空隙。通信协议、Flash 存储和寄存器映射中，如果直接使用结构体对应二进制数据，就必须特别注意对齐和字节布局。

## 7. 函数指针：把行为当作参数传递

函数指针保存的是函数地址。它可以让程序在运行时选择调用哪个函数。

课程里提到 `qsort` 回调，这是函数指针的经典例子。排序函数本身不知道比较规则，所以把比较函数作为参数传进去。

在嵌入式中，函数指针常用于：

- 回调函数
- 状态机
- 驱动抽象层
- 通信协议命令分发
- 中断事件处理

比如串口收到一条命令后，可以根据命令号调用不同处理函数。这样代码比一长串 `if-else` 更清晰。

函数指针语法难读，但它表达的思想很重要：数据可以传递，行为也可以传递。

## 8. 位运算：嵌入式寄存器控制的基本动作

位运算是 C 语言和嵌入式之间最直接的接口。

常用位运算包括：

- `&`：按位与
- `|`：按位或
- `^`：按位异或
- `~`：按位取反
- `<<`：左移
- `>>`：右移

寄存器通常由很多位组成，每一位或几位控制一个功能。比如某一位控制时钟使能，某几位选择 GPIO 模式，某一位表示中断标志。

常见操作模式是：

```text
设置某一位：reg |= mask
清除某一位：reg &= ~mask
翻转某一位：reg ^= mask
读取某一位：reg & mask
```

这部分是 STM32 寄存器编程的基础。理解位运算后，才能理解为什么写一个寄存器值就能打开时钟、配置输出模式或清除中断标志。

## 9. 宏与预处理器：编译前的文本处理

宏是在预处理阶段完成的文本替换。它可以定义常量、封装简单表达式、控制条件编译。

宏很强，但也容易出问题。比如宏参数如果不加括号，可能因为运算优先级导致错误。因此宏的基本习惯是：参数加括号，整体也加括号。

条件编译常用于嵌入式：

```c
#ifdef DEBUG
    // 调试代码
#endif
```

它可以让同一份代码在调试版、发布版、不同芯片型号或不同硬件配置下编译出不同结果。

`#include` 的本质是把头文件内容复制进来。头文件通常放函数声明、类型定义、宏定义和外部变量声明。源文件放函数实现和变量定义。

## 10. 编译与链接：多文件工程怎样组织起来

真实嵌入式工程不会把所有代码写在一个 `.c` 文件里。它通常会拆成多个模块：

- `main.c`：主程序
- `delay.c`：延时函数
- `led.c`：LED 驱动
- `key.c`：按键驱动
- `oled.c`：显示驱动
- `usart.c`：串口驱动
- `sensor.c`：传感器驱动

这就需要理解声明和定义。

声明告诉编译器“这个函数或变量存在，长这样”。

定义真正分配空间或提供函数实现。

头文件用于共享声明，源文件用于提供定义。

多文件编译最后要靠链接器把各个模块合并起来。Make、CMake 或 IDE 工程配置，都是在帮助管理编译和链接过程。

静态库和动态库也是链接阶段的重要概念。嵌入式项目中常见的是静态链接，把所需代码一起打进最终固件。

## 11. 常见陷阱

C 语言常见问题包括：

- 指针未初始化
- 数组越界
- 字符串缺少 `\0`
- `sizeof` 用错对象
- `malloc` 后忘记 `free`
- `free` 后继续使用指针
- 宏缺少括号
- 头文件重复包含
- 声明和定义混淆
- 有符号和无符号混用

这些问题在普通程序里可能只是崩溃，在设备控制里可能表现为误触发、通信异常、传感器读数错误、电机动作异常或系统死机。

所以 C 语言学习不能只追求语法会写，还要形成底层安全意识。

## 12. 嵌入式接口预览

C 语言学习最后会自然过渡到嵌入式接口：

- 通过指针访问寄存器地址。
- 通过位运算配置寄存器字段。
- 通过结构体组织设备状态。
- 通过函数封装驱动接口。
- 通过宏定义引脚、端口、命令和标志位。
- 通过 `volatile` 处理硬件寄存器和中断变量。
- 通过多文件工程组织驱动、业务和系统模块。

这正好连接到 STM32 课程。

# 三、STM32 部分

STM32 课程主要讲开发环境搭建和嵌入式项目的完整周期。

课程基于江协科技 STM32 入门教程，内容覆盖 50 集、15 章，总时长约 33 小时 30 分钟。它不是单纯讲概念，而是围绕真实硬件实验展开：LED、蜂鸣器、按键、光敏传感器、红外模块、旋转编码器、OLED、直流电机、舵机、MPU6050、W25Q64 等。

STM32 学习的主线是：

```text
认识芯片和开发环境
-> 建立工程
-> 控制 GPIO
-> 接入输入输出设备
-> 使用中断和定时器
-> 采集模拟量
-> 使用 DMA 提高效率
-> 用串口/I2C/SPI 通信
-> 管理时间、电源、看门狗和存储
```

## 第1章：课程与 STM32 概述

课程首先介绍硬件套件和 STM32 基本情况。

用到的硬件包括 STM32 最小系统板、面包板、杜邦线、OLED 显示屏、ST-Link、USB 转串口模块、Flash 存储器、蜂鸣器、光敏传感器、热敏传感器、红外模块、旋转编码器、LED、直流电机、电机驱动模块和舵机。

这些模块覆盖了设备控制里的几个基本类型：

- 输入：按键、光敏、热敏、红外、编码器、MPU6050。
- 输出：LED、蜂鸣器、OLED、舵机、电机。
- 通信：串口、I2C、SPI。
- 存储：外部 Flash、内部 Flash、备份寄存器。

STM32 的核心来自 ARM，芯片由 ST 意法半导体设计和生产。课程中使用的 STM32F103C8T6 是常见入门型号。

这一章还讲芯片引脚、最小系统板结构、BOOT 引脚、复位按键、晶振、电源指示灯、SWD 下载接口、稳压芯片和外围电路。

对设备控制来说，这一章建立一个重要认识：单片机不是一块抽象计算板，它由内核、总线、外设、引脚、电源和时钟共同组成。程序控制设备，本质上是配置这些硬件资源。

## 第2章：开发环境搭建

开发环境主要包括 Keil5 MDK、器件支持包、ST-Link 驱动和 USB 转串口驱动。

课程讲了新建 STM32 工程的过程。一个 STM32 工程不只是 `main.c`，还需要启动文件、芯片头文件、系统时钟配置文件、内核支持文件、外设库文件和用户代码。

启动文件是 `.s` 汇编文件，负责芯片上电后的最早期启动过程。它会设置中断向量表，最终跳到 `main` 函数。

`stm32f10x.h` 描述了 STM32 外设寄存器和地址。它让 C 程序可以用结构体和宏访问寄存器。

`system_stm32f10x.c/h` 负责系统时钟配置。

`core_cm3.c/h` 提供 Cortex-M3 内核相关定义和函数。

课程介绍了三种开发方式：

1. 寄存器开发：直接写寄存器，最贴近硬件。
2. 标准库开发：使用 ST 官方标准外设库函数，降低寄存器配置难度。
3. HAL 库开发：更高级、更跨系列的库，屏蔽更多芯片差异。

寄存器方式能帮助理解底层原理，库函数方式更适合实际快速开发。学习时最好先知道寄存器在做什么，再用库函数提高效率。

## 第3章：GPIO

GPIO 是通用输入输出口，是最基础的外设。

GPIO 输出可以控制 LED、蜂鸣器、继电器、电机驱动输入等。课程先讲 GPIO 的内部结构，包括输入驱动、输出驱动、保护二极管、推挽输出、开漏输出等。

LED 实验用于理解输出控制。程序配置 GPIO 为输出模式，然后通过设置输出寄存器控制引脚高低电平，从而让 LED 亮灭。

LED 闪烁和流水灯用于练习延时函数、循环控制和多个引脚组合控制。

蜂鸣器实验说明 GPIO 不只控制灯，也可以控制声音输出。

GPIO 输入用于读取外部状态，比如按键、光敏传感器。按键控制 LED、光敏传感器控制蜂鸣器，说明了设备控制里最基本的闭环：

```text
读取输入 -> 判断状态 -> 控制输出
```

这也是后面复杂控制系统的原型。

## 第4章：OLED 调试与显示

OLED 显示屏用于调试和显示状态。

在没有复杂调试工具时，OLED 可以直接显示变量、传感器数据、运行状态和错误信息。它让单片机程序从“看不见内部状态”变成“可以观察运行结果”。

课程先介绍 OLED 调试工具，再讲 OLED 显示屏的使用。实际项目中，OLED 常作为调试界面或小型设备的人机界面。

这一章的价值不只是会点亮屏幕，而是学会给嵌入式程序增加可观察性。

## 第5章：EXTI 外部中断

外部中断用于让单片机在外部事件发生时立即响应。

如果不用中断，程序只能一直轮询按键或传感器状态。轮询简单，但效率低，也可能错过短暂事件。

中断的思路是：外部信号变化时，硬件主动打断当前程序，跳到中断服务函数处理事件。

课程讲了 EXTI 外部中断，并用对射式红外传感器计次、旋转编码器计次做实验。

对射式红外模块可以检测遮挡次数，适合计数场景。旋转编码器可以检测旋转动作，适合旋钮输入或速度测量。

中断让设备能更及时地响应外部世界，是实时控制的基础。

## 第6章：TIM 定时器

定时器是 STM32 里非常核心的外设。这一章内容最多，覆盖定时中断、外部时钟、输出比较、PWM、输入捕获和编码器接口。

定时中断用于周期性执行任务。比如每 1ms 扫描按键，每 10ms 采集传感器，每 100ms 更新显示，每 1s 统计状态。

外部时钟模式可以让定时器根据外部脉冲计数。

输出比较可以在计数器到达某个值时改变输出状态。

PWM 是设备控制中极其常见的信号。它通过调节占空比控制平均输出功率。课程用 PWM 驱动 LED 呼吸灯、舵机和直流电机。

LED 呼吸灯说明 PWM 可以调亮度。

舵机控制说明 PWM 可以表示角度位置。

直流电机调速说明 PWM 可以控制电机速度。

输入捕获用于测量输入信号的频率、周期或脉宽。PWMI 模式可以测频率和占空比。

编码器接口用于读取编码器信号，进而实现测速。电机控制中，编码器反馈是速度闭环和位置闭环的重要来源。

这一章把设备控制推到核心区域：时间、频率、占空比、速度和反馈。

## 第7章：ADC 模数转换器

ADC 用于把模拟电压转换成数字量。

很多传感器输出的是模拟信号，比如光敏电阻、热敏电阻、电位器、某些压力或电流传感器。单片机不能直接理解连续电压，必须通过 ADC 采样成数字值。

课程讲 ADC 基本概念，以及单通道和多通道采集。

单通道适合读取一个模拟量。多通道适合同时读取多个传感器输入。

设备控制中，ADC 是“读取真实世界连续变化”的入口。温度、光照、电压、电流等信号，都常通过 ADC 进入程序。

## 第8章：DMA 直接存储器存取

DMA 可以在外设和内存之间自动搬运数据，减少 CPU 参与。

没有 DMA 时，CPU 需要不断读外设、写内存。如果数据量大或采样频率高，CPU 会被搬运数据占用。

DMA 的意义是让硬件帮忙搬数据。CPU 只需要配置源地址、目标地址、数据长度和触发条件。

课程讲 DMA 数据转运，以及 DMA 配合 ADC 多通道采样。

这对于设备控制很重要。比如连续采集传感器数据时，DMA 可以把 ADC 数据自动放进数组，CPU 只在需要处理时读取缓冲区。这样系统更高效，也更稳定。

## 第9章：USART 串口

USART 是最常用的串口通信外设。

串口可以让 STM32 和电脑、其他单片机、蓝牙模块、Wi-Fi 模块、调试工具通信。课程讲串口协议、串口外设、发送、接收、数据包和下载工具。

串口发送可以用于打印调试信息。比如输出传感器数据、当前状态、错误码。

串口接收可以用于接收电脑或上位机命令。比如设置参数、切换模式、控制电机。

课程还讲 HEX 数据包和文本数据包。HEX 包更适合机器解析，文本包更适合人调试。

串口数据包引入了通信协议意识：一条完整消息通常需要包头、长度、命令、数据和校验。否则接收端很难判断哪里是一条消息的开始和结束。

FlyMcu 和 STLINK Utility 用于下载和工具操作，帮助理解除了 Keil 之外的烧录方式。

## 第10章：I2C 通信

I2C 是常见的板级通信总线，适合连接传感器、EEPROM、RTC、OLED 等低速外设。

I2C 通常使用两根线：SCL 时钟线和 SDA 数据线。总线上可以挂多个设备，每个设备通过地址区分。

课程先讲 I2C 通信协议，再以 MPU6050 为例。MPU6050 是陀螺仪和加速度计，可以测量姿态相关数据，常用于平衡车、无人机、姿态检测和运动感知。

课程分别实现软件 I2C 和硬件 I2C 读写 MPU6050。

软件 I2C 是用 GPIO 模拟协议时序。它有助于理解协议细节。

硬件 I2C 是使用 STM32 自带 I2C 外设。它效率更高，更适合实际工程。

这一章让设备可以连接复杂传感器，是从简单输入输出走向真实感知系统的关键。

## 第11章：SPI 通信

SPI 也是常用通信总线，速度通常比 I2C 更快。

SPI 常用信号包括 SCK、MOSI、MISO 和片选线 CS。它适合连接 Flash、显示屏、ADC、无线模块等。

课程先讲 SPI 通信协议，再以 W25Q64 Flash 存储器为例。W25Q64 是外部 Flash，可以用于保存数据、参数、日志或资源。

课程分别实现软件 SPI 和硬件 SPI 读写 W25Q64。

软件 SPI 帮助理解时序，硬件 SPI 更适合工程使用。

和 I2C 相比，SPI 通常速度快、协议简单，但占用引脚更多。设备控制中要根据外设要求、速度要求和引脚资源选择通信方式。

## 第12章：BKP 与 RTC

这一章讲 Unix 时间戳、备份寄存器和 RTC 实时时钟。

Unix 时间戳是一种用秒数表示时间的方式，适合程序计算和存储。

RTC 可以让单片机记录真实时间。它常用 32.768kHz 晶振，即使主系统休眠，也可以继续计时。

BKP 备份寄存器可以在特定供电条件下保留少量数据。比如保存启动标志、校准值或关键状态。

设备控制中，时间非常重要。日志记录、定时任务、低功耗唤醒、数据采样时间戳，都需要 RTC 支持。

## 第13章：PWR 电源控制

PWR 电源控制用于管理功耗和运行模式。

课程讲修改主频、睡眠模式、停止模式和待机模式。

修改主频会影响性能和功耗。频率高，计算快，但耗电多；频率低，省电，但处理能力下降。

睡眠、停止、待机模式是不同层次的低功耗模式。设备在不需要一直工作时，可以进入低功耗状态，等待中断或 RTC 唤醒。

这对电池供电设备非常关键。比如传感器节点、便携设备、远程监测设备，不能一直高功耗运行。

## 第14章：WDG 看门狗

看门狗用于防止程序卡死后无人恢复。

程序需要定期“喂狗”。如果程序跑飞、死循环或阻塞，不能及时喂狗，看门狗就会复位系统。

课程讲独立看门狗和窗口看门狗。

独立看门狗使用独立时钟，可靠性更强，适合系统级保护。

窗口看门狗要求在规定时间窗口内喂狗，太早或太晚都不行，能发现更多异常时序问题。

设备控制系统常常要长期运行。看门狗是一种工程保险，保证系统异常时可以自动恢复。

## 第15章：FLASH 闪存

Flash 用于非易失存储。断电后数据仍然保留。

课程讲内部 Flash 的读写，以及读取芯片 ID。

内部 Flash 可以用于保存配置参数、校准数据、设备编号、运行次数等。外部 Flash 则适合保存更多数据，比如日志、波形、资源或历史记录。

Flash 操作需要注意擦除和写入粒度，也要注意寿命。Flash 不能像 RAM 一样无限次随便写，频繁写入要设计磨损均衡或减少写次数。

读取芯片 ID 可以用于设备身份识别、绑定、序列号或防止混淆。

# 四、完整嵌入式项目周期

个人总结里提到 STM32 项目的完整周期，这一点很重要。

一个设备控制项目通常不是直接写 `main`，而是从硬件理解开始：

```text
阅读设备手册
-> 确认电气特性和通信方式
-> 搭建最小测试电路
-> 编写单个驱动
-> 验证驱动功能
-> 组合多个传感器和执行器
-> 写主程序业务逻辑
-> 调试、优化、异常保护
-> 固化为完整设备程序
```

阅读设备手册是第一步。因为传感器和执行器不是抽象模块，它们有供电电压、引脚定义、通信时序、寄存器地址、数据格式、最大电流、采样频率和初始化流程。

驱动代码负责把硬件细节封装起来。比如 `MPU6050_ReadData()` 隐藏 I2C 读寄存器细节，`OLED_ShowString()` 隐藏显示屏通信细节，`Motor_SetSpeed()` 隐藏 PWM 配置细节。

主函数负责组合驱动，形成业务流程。比如：

```text
初始化时钟
初始化 GPIO
初始化 OLED
初始化串口
初始化传感器
初始化定时器和中断
while(1) {
    读取传感器
    处理数据
    控制执行器
    更新显示
    通过串口发送状态
}
```

随着项目变复杂，主循环里不能什么都塞。需要按模块拆分代码，用定时器、中断、缓冲区、状态机和通信协议来组织系统。

# 五、C 和 STM32 的对应关系

C 语言知识和 STM32 外设不是两套东西，而是一一对应的。

| C 语言能力 | STM32 中的用途 |
|---|---|
| 编译与链接 | 建工程、加启动文件、加库文件、配置头文件路径 |
| 类型系统 | 定义寄存器值、传感器数据、通信字段 |
| 指针 | 访问寄存器、传递缓冲区、修改外部变量 |
| 数组 | 保存采样数据、串口缓冲区、显示缓存 |
| 字符串 | 串口文本通信、调试输出 |
| 结构体 | 封装外设配置、传感器数据、通信包 |
| 函数指针 | 回调、中断事件、状态机、命令分发 |
| 位运算 | 设置/清除寄存器位、处理标志位 |
| 宏 | 定义引脚、端口、寄存器位、条件编译 |
| volatile | 硬件寄存器、中断变量、防止错误优化 |

这张表说明：学习 C 不是为了“会一门语法”，而是为了能读懂并写出设备驱动。

# 六、放在设备控制中的最终理解

设备控制程序的核心闭环是：

```text
感知输入 -> 计算判断 -> 控制输出 -> 反馈修正
```

GPIO 输入、ADC、I2C、SPI、USART 负责感知和通信。

定时器、中断、DMA 负责让系统按正确时间和效率运行。

GPIO 输出、PWM、舵机、电机驱动负责控制动作。

OLED、串口、Flash、RTC 负责显示、调试、记录和保存状态。

看门狗和电源控制负责可靠性和低功耗。

C 语言则贯穿所有环节。它把这些外设封装成驱动函数，再由主程序组合成完整业务。

# 八、最后总结

这部分课程的主线很清楚：先用 C 语言建立底层编程能力，再用 STM32 把这些能力落到真实硬件控制上。

C 语言部分解决“程序如何贴近内存和硬件”。重点是指针、数组、结构体、位运算、宏、编译链接和 `volatile`。这些内容都是写嵌入式驱动必须掌握的基础。

STM32 部分解决“程序如何控制真实设备”。从 GPIO 到定时器，从 ADC 到 DMA，从串口到 I2C/SPI，再到 RTC、电源、看门狗和 Flash，覆盖了一个单片机项目最常见的外设能力。

放在设备控制方向看，最终目标不是孤立地会写 C 或会点亮 LED，而是能完成完整流程：

1. 看懂硬件手册。
2. 搭建工程和开发环境。
3. 编写并验证单个外设驱动。
4. 组合多个传感器和执行器。
5. 在主程序中实现业务控制逻辑。
6. 加入通信、显示、存储、低功耗和异常保护。

也就是说，这门“编程”总结对应的是设备控制的底座能力：把代码写进芯片，让芯片读懂外部世界，并按程序控制真实硬件动作。
