# 一、总体脉络

设备控制可以拆成四个模块：

1. 编程：把程序写进设备，让设备能读取传感器、控制执行器、运行主流程。
2. 机器学习：让系统从数据中学习规律，用来识别、预测、分类、推荐和决策。
3. 自动控制：让设备根据反馈稳定地达到目标，比如速度稳定、位置准确、倒立摆不倒。
4. 项目：把编程、机器学习和自动控制组合成可以运行、可以验证的实验系统。

可以用一句话概括：

```text
编程负责实现，机器学习负责学习规律，自动控制负责稳定动作，项目负责综合落地。
```

如果把设备控制看成一个闭环系统，它的路径大概是：

```text
传感器采集数据
-> 程序读取和处理数据
-> 机器学习模型识别或预测状态
-> 控制算法计算控制量
-> 执行器产生动作
-> 新状态再次被传感器反馈
```

所以，这四个模块不是孤立的。编程是底座，机器学习提供智能，自动控制保证稳定，项目把它们连成完整系统。

# 二、编程模块

编程模块主要解决一个问题：怎样把算法和业务逻辑真正运行在设备上。

这一块可以分成四部分：

1. C 语言：用于底层驱动和嵌入式程序。
2. C++：用于业务层封装和工程结构。
3. Python / PyTorch：用于模型实现、训练、验证和可视化。
4. STM32：用于真实嵌入式设备开发。

## 1. C 语言

C 语言是设备端开发的基础。它贴近硬件，运行开销低，适合写驱动、外设控制和主程序逻辑。

需要掌握的重点包括：

1. 指针：理解地址、内存访问、数组传参和结构体传参。
2. 宏定义：用于常量、条件编译和简单代码封装。
3. 类型定义：理解 `typedef`、整数类型、浮点类型、`const`、`volatile`。
4. 结构体：把传感器、电机、通信包等数据组织成一个整体。
5. 位运算：用于寄存器配置、状态位读取和硬件控制。
6. 编译链接：理解 `.c`、`.h`、目标文件、链接和固件生成过程。

在设备控制里，C 语言常见的用途是：

```text
读传感器数据
配置 GPIO、定时器、串口、ADC、I2C、SPI
输出 PWM 控制电机
处理中断
维护缓冲区和状态变量
```

可以说，C 语言负责让程序真正碰到硬件。

## 2. C++

C++ 在 C 的基础上加入了类、对象、封装等概念，更适合组织中大型工程。

在设备控制里，可以把传感器、执行器、控制器封装成类。例如：

```text
Sensor 类负责读取数据
Motor 类负责控制电机
PID 类负责计算控制量
System 类负责组织主流程
```

这样做的好处是代码结构更清楚，也更容易复用。

不过在嵌入式环境中使用 C++ 时，需要注意资源限制。比如有些项目会关闭异常处理、谨慎使用动态内存，避免运行时开销过大。

C++ 的作用可以概括为：

```text
用更清晰的工程结构组织设备控制程序。
```

## 3. Python 和 PyTorch

Python 在设备控制中主要用于上位机、数据处理、模型训练、验证和可视化。

PyTorch 是深度学习框架，主要用于实现和训练神经网络模型。常见概念包括：

1. Tensor：保存数据和模型参数。
2. `nn.Linear`：也就是全连接层，用来构建神经网络层。
3. Autograd：自动求导，用于反向传播。
4. `zero_grad()`：每次反向传播前清空梯度。
5. `train()` 和 `eval()`：切换训练模式和推理模式。
6. 模型保存与加载：用于训练后部署或继续训练。

在设备控制里，PyTorch 常用于：

```text
训练故障检测模型
训练图像识别模型
训练时序预测模型
验证模型效果
画损失曲线和预测结果
```

训练好的模型可以在电脑端运行，也可以进一步转换后部署到边缘设备或嵌入式系统中。

## 4. STM32 开发流程

STM32 是常见的嵌入式开发平台。它把 C 语言、外设驱动和真实硬件连接起来。

一个典型 STM32 项目的流程是：

1. 阅读硬件手册，了解芯片、传感器和执行器的工作机理。
2. 配置工程环境，比如 Keil MDK。
3. 编写或封装底层驱动。
4. 读取传感器数据。
5. 控制执行器，比如 LED、电机、舵机、蜂鸣器。
6. 编写主程序，把多个模块组合成业务流程。
7. 用串口、OLED、SerialPlot 等工具调试。

常见外设包括：

```text
GPIO、定时器、PWM、ADC、DMA、USART、I2C、SPI、RTC、Flash、看门狗
```

编程模块最终要达到的目标是：能把一个控制想法写成真实设备上可以运行的程序。

# 三、机器学习模块

机器学习模块主要解决一个问题：怎样让设备从数据里学习规律。

传统程序依赖人工写规则。机器学习则是从样本中学习输入和输出之间的关系。比如：

```text
传感器数据 -> 是否故障
图像 -> 物体类别
历史用电数据 -> 下一时刻负荷
状态和动作 -> 更好的控制策略
```

机器学习和深度学习可以分成几类内容。

## 1. 监督学习

监督学习的特点是训练数据有明确答案。

典型任务包括：

1. 线性回归：预测连续数值，比如房价、温度、能耗、负荷。
2. 逻辑回归：做二分类，比如肿瘤良恶性、设备是否故障。
3. 多分类：判断图像或状态属于哪一类。

线性回归的核心形式是：

```text
f(x) = wx + b
```

它适合做数值预测。

逻辑回归用于分类，核心是把线性结果经过 sigmoid 函数变成 0 到 1 的概率。

监督学习的基本训练流程是：

```text
输入数据 -> 模型预测 -> 计算误差 -> 梯度下降更新参数 -> 再预测
```

这一流程也是后面神经网络训练的基础。

## 2. 传统机器学习算法

除了线性回归和逻辑回归，还需要了解一些传统算法：

1. 决策树：通过一系列判断条件完成分类或回归。
2. 随机森林：把多棵决策树组合起来，提高稳定性。
3. XGBoost：常用于结构化表格数据，适合故障诊断、风险评分等任务。
4. K-means：无监督聚类，用于发现数据中的自然分组。
5. 异常检测：学习正常状态，发现偏离正常模式的数据。

在设备控制中，这些算法可以用于：

```text
工况分类
故障诊断
状态识别
异常检测
维护预测
```

如果数据是传感器统计特征、设备运行记录、维护记录等表格数据，传统机器学习方法往往很实用。

## 3. 深度学习

深度学习主要使用多层神经网络学习复杂特征。

基本概念包括：

1. 神经元：接收输入，计算加权和，再经过激活函数输出。
2. 前向传播：数据从输入层一层一层算到输出层。
3. 反向传播：根据误差计算梯度，更新模型参数。
4. 激活函数：比如 sigmoid、ReLU、softmax。
5. 损失函数：衡量预测结果和真实结果的差距。
6. 优化器：比如 SGD、Adam。

深度学习适合处理复杂数据，比如图像、语音、文本和长时间序列。

## 4. 视觉与识别任务

视觉任务主要用 CNN 或更复杂的深度学习模型。

常见项目包括：

1. 图像分类：识别猫、狗、车、人等类别。
2. YOLO 目标检测：在图像中找到目标位置和类别。
3. 人脸识别：判断人脸身份或做人脸验证。
4. 工业视觉检测：识别缺陷、零件、目标物体。

在设备控制里，视觉模型可以作为“感知模块”。例如机器人先通过摄像头识别目标，再由控制算法决定怎样运动。

## 5. 序列任务

设备控制经常遇到时间序列数据，比如温度、电流、振动、用电负荷、速度曲线等。

这类任务可以使用：

1. RNN：处理序列数据的基础模型。
2. LSTM：更适合处理长序列，能缓解长期依赖问题。
3. GRU：结构比 LSTM 更简单，也常用于时序任务。
4. Transformer：适合更复杂的序列建模。

个人总结中特别提到一个实验：LSTM 用电负荷预测。

这个实验的意义是：设备控制系统不只需要知道当前状态，还常常需要预测未来状态。例如预测未来负荷、温度变化或故障趋势。

## 6. 强化学习

强化学习和控制问题关系很近。

它不是直接给模型标准答案，而是让智能体在环境中试错，通过奖励学习策略。

核心概念包括：

1. 状态：当前环境是什么样。
2. 动作：智能体可以做什么。
3. 奖励：动作带来的好坏反馈。
4. 策略：在某个状态下选择动作的方法。
5. 价值函数：衡量某个状态或动作长期来看有多好。

课程中提到月球着陆器、火星探测器等实验。这些任务很适合理解强化学习，因为它们本质上都是：

```text
观察状态 -> 选择动作 -> 环境变化 -> 获得奖励 -> 继续调整策略
```

强化学习可以用于机器人、无人车、飞行器、能源调度等连续决策问题。

# 四、自动控制模块

自动控制模块主要解决一个问题：怎样让设备稳定、准确、快速地达到目标。

控制系统的基本闭环是：

```text
目标值 -> 控制器 -> 执行器 -> 被控对象 -> 传感器反馈 -> 和目标值比较 -> 再控制
```

比如：

1. 电机速度低于目标，就增大 PWM。
2. 温度低于目标，就增加加热功率。
3. 倒立摆向一边倒，就让小车移动去接住它。

自动控制的重点不是简单输出一个动作，而是根据反馈不断修正动作。

## 1. PID 控制

PID 是最常用的控制算法，由三部分组成：

1. P：比例项，根据当前误差调节。
2. I：积分项，消除长期累计误差。
3. D：微分项，根据误差变化趋势提前抑制。

可以简单理解为：

```text
P 看现在，I 看过去，D 看趋势。
```

PID 的常见应用包括：

1. 电机定速控制。
2. 电机定位控制。
3. 温度控制。
4. 倒立摆控制。

PID 的优点是简单、直观、容易落地。很多实际设备控制项目，第一版控制器都会先从 PID 开始。

## 2. MPC 模型预测控制

MPC 的思想是：先用模型预测未来一段时间系统会怎样变化，再在约束条件下选择最优控制动作。

它的基本流程是：

```text
获取当前状态
-> 预测未来多个时刻的状态
-> 在约束下优化控制序列
-> 只执行第一个控制动作
-> 下一次采样后重新预测和优化
```

MPC 适合处理有约束、多变量、动态较慢或需要提前规划的系统。

例如：

1. 机械臂控制。
2. 自动驾驶轨迹控制。
3. 能源调度。
4. 化工过程控制。

相比 PID，MPC 更复杂，但表达能力更强。

## 3. 自动控制理论基础

自动控制还需要一些基础理论。

### 状态空间

状态空间用状态变量描述系统内部动态。常见形式是：

```text
x' = Ax + Bu
y  = Cx + Du
```

其中：

1. `x` 是状态。
2. `u` 是输入。
3. `y` 是输出。
4. `A、B、C、D` 描述系统关系。

状态空间适合描述多变量系统，也适合现代控制方法，比如 LQR、观测器、可控性和可观测性分析。

### 拉普拉斯变换

拉普拉斯变换可以把微分方程变成代数方程。

在控制系统中，它常用于：

1. 分析系统稳定性。
2. 推导传递函数。
3. 观察极点和系统响应。
4. 理解振荡、超调、衰减和稳定。

直观地说，拉普拉斯变换帮助我们从数学上理解系统为什么会稳定、发散或振荡。

### 模糊控制

模糊控制适合系统模型不清楚，但人有经验规则的场景。

它不一定需要精确数学模型，而是使用类似这样的规则：

```text
如果误差很大，就强力调节
如果误差较小，就轻微调节
如果变化太快，就提前抑制
```

这种方法适合一些经验性强、难以精确建模的控制任务。

# 五、项目模块

项目模块负责把前面的知识组合起来。

可以分成四类项目：

1. 编程和嵌入式项目。
2. 机器学习项目。
3. 深度学习项目。
4. 自动控制项目。

## 1. 编程和嵌入式项目

这一类项目主要围绕 STM32 和外设控制。

典型项目包括：

1. 对射式红外传感器计次实验。
2. 电机定速控制实验。
3. 电机定位控制实验。
4. 双环 PID 倒立摆实验。

这些实验能训练三种能力：

1. 写驱动：让传感器和执行器能工作。
2. 写主程序：把多个模块组织成完整流程。
3. 调试设备：通过串口、OLED、SerialPlot 等工具观察状态。

## 2. 机器学习项目

机器学习项目主要用来理解监督学习、无监督学习和推荐系统。

典型实验包括：

1. 线性回归：房价预测。
2. 逻辑回归：肿瘤分类。
3. K-means：故障检测或工况聚类。
4. 推荐系统：协同过滤。
5. 强化学习：月球着陆器、火星探测器。

这些实验的共同流程是：

```text
准备数据
-> 选择模型
-> 定义损失函数或奖励
-> 训练模型
-> 评价效果
-> 分析错误并改进
```

放在设备控制场景中，机器学习项目可以帮助系统完成识别、预测和辅助决策。

## 3. 深度学习项目

深度学习项目主要处理图像、文本、语音和序列。

典型项目包括：

1. 图像分类：猫、狗、车、人等类别识别。
2. YOLO：目标检测。
3. 人脸识别：身份识别或人脸验证。
4. 触发词检测：从音频中识别关键词。
5. 英法翻译：序列到序列模型。
6. LSTM 用电负荷预测：根据历史序列预测未来负荷。

这些项目的意义是让设备具备更复杂的感知能力和预测能力。

例如，一个智能设备可以：

```text
用摄像头识别目标
用声音识别指令
用传感器序列预测故障
用历史数据预测未来负荷
```

## 4. 自动控制项目

自动控制项目主要验证控制算法能否让设备稳定动作。

典型实验包括：

1. PID 电机定速控制。
2. PID 电机定位控制。
3. 双环 PID 倒立摆。
4. MPC 机械臂控制仿真。
5. 模糊控制洗衣机。

这些项目的核心不是只让设备动起来，而是让设备按照目标稳定地动。

例如电机控制中，需要关注：

1. 是否达到目标速度或位置。
2. 是否超调。
3. 是否震荡。
4. 稳态误差是否足够小。
5. 响应速度是否合适。

倒立摆实验更能体现闭环控制的特点。系统必须不断读取角度和位置，再通过双环 PID 计算电机动作，才能让摆杆保持平衡。

# 六、四个模块之间的关系

这四个模块可以放在一个完整设备系统里理解。

以智能电机控制系统为例：

1. C 语言写编码器读取、电机 PWM、串口通信等底层驱动。
2. C++ 把电机、传感器、PID 控制器封装成对象。
3. STM32 运行实时控制程序。
4. PID 控制电机速度或位置。
5. SerialPlot 显示波形，用于观察误差和调参。
6. PyTorch 训练故障检测或负荷预测模型。
7. 机器学习模型辅助判断异常状态。
8. 项目把这些模块组合成一个能感知、能判断、能控制、能调试的系统。

对应关系可以这样记：

```text
C / STM32：让设备能动
C++：让程序结构更清楚
PyTorch：让模型能训练
机器学习：让系统能识别和预测
自动控制：让动作稳定和准确
项目：让所有知识变成完整系统
```

# 七、最终总结

设备控制学习的主线可以总结成四句话。

第一，编程是底座。没有 C、C++、Python、PyTorch、STM32，就很难把算法和业务逻辑落到真实设备上。

第二，机器学习提供智能。它让系统能从数据中学习，完成识别、预测、分类、推荐和策略学习。

第三，自动控制提供稳定。它让设备不是随便动作，而是根据反馈稳定地达到目标。

第四，项目负责集成。真实设备控制不是单点知识，而是把驱动、传感器、模型、控制算法、执行器和调试工具放在一起。

最终可以用一条能力链概括：

```text
编程实现底层能力
-> 机器学习提供识别和预测
-> 自动控制保证动作稳定
-> 项目把三者组合成真实系统
```

这就是设备控制四个模块的整体框架。
