# 嵌入式基础：从点亮 LED 到 PID 电机控制

> AI 结构化笔记 | 2026-06-15

---

## 锚点：你想让一个电机动起来，精确地转到你想要的位置

一台电机，接上电就傻转。你想让它停在 30°，它不行。你想让它加速到 1000 转/分，然后稳住，它也不行。

你需要的是一整套能力，从"能跟物理世界说话"，到"能感知现在转到哪了"，再到"能自己算出该加多少力"。

这就是嵌入式系统做的事。我们按这个线索展开。

---

## 一、什么是嵌入式系统

### 一句话

嵌入式系统就是**藏在某个设备里的小电脑**，它只干一件事，但干得很好。

你的笔记本电脑是通用计算机——能打游戏、写代码、看视频。嵌入式系统不是。它藏在微波炉里，只负责控制加热时间；藏在电机驱动器里，只负责让转子转到正确位置。

**核心区别**：

| | 通用计算机 | 嵌入式系统 |
|---|---|---|
| 做什么 | 什么都能做 | 只做一件事 |
| 资源 | CPU 强劲、内存大 | CPU 弱、内存小（KB 级别） |
| 操作系统 | Windows/Linux/macOS | 裸机程序或轻量 RTOS |
| 实时性 | "尽量快" | "必须在 1ms 内响应" |
| 功耗 | 不在乎 | 吃干电池也能活一年 |

### 单片机（MCU）是什么

MCU = 一颗芯片上集成了：CPU + 内存(Flash/RAM) + 外设(GPIO、定时器、串口、ADC...)

你可以把它想象成**一个连键盘显示器都没有的迷你电脑**，给它供电它就干活，程序烧进去就永远跑那一段。常见的 STM32 就是这类芯片。

### 程序怎么跑进去的

你写 C 代码 → 编译成机器码 → 通过调试器(ST-Link/J-Link)烧进芯片的 Flash → 上电自动跑。

不像 PC 从硬盘加载程序，嵌入式系统的程序就住在 Flash 里，断电不丢，上电就跑。

## 二、GPIO：和物理世界的第一次对话

### 这是什么

GPIO = General Purpose Input/Output，通用输入输出引脚。

**大白话：芯片上一根可以编程控制的金属腿。** 你可以让它输出高电平(3.3V)或低电平(0V)，也可以读取它上面的电压是高是低。

这就是嵌入式最基本的能力：**输出，控制东西；输入，感知东西。**

### 输出模式

**推挽输出（Push-Pull）**：能推高也能拉低，驱动能力强。你用它点亮 LED，驱动继电器。

电路上：芯片内部有两个开关，一个连 VDD(3.3V)，一个连 GND。开上面、关下面，输出高电平；反过来输出低电平。两个都不开，就是高阻态（相当于这根腿暂时没人管）。

**开漏输出（Open-Drain）**：只能拉低，不能推高。要实现高电平，得在芯片外面接一个上拉电阻到 VDD。

你问为什么搞这么麻烦？因为 I²C 这种总线协议要求"谁都能把线拉低，但谁都不准主动拉高"，只能靠上拉电阻。开漏模式正好实现这个。

### 输入模式

读引脚上的电压：高于某个阈值就是逻辑 1，低于阈值就是 0。

**上拉/下拉**：如果在输入模式不接上下拉电阻，当外部什么都没接时，引脚电平是悬空的——可能读到 0 也可能读到 1，完全随噪声漂。上拉就是内部给你接了个电阻到 VDD（默认高），下拉就是接到 GND（默认低）。按键检测常用上拉：平时读到高电平，按下接通 GND 读到低电平，说明有人按了。

### 代码视角

用 STM32 HAL 库，点个灯的流程是：

1. 使能 GPIO 时钟（芯片为了省电，默认关着所有外设的时钟）
2. 配置引脚为输出模式
3. 写 `HAL_GPIO_WritePin(LED_PORT, LED_PIN, GPIO_PIN_SET)` — 亮
4. 写 `HAL_GPIO_WritePin(LED_PORT, LED_PIN, GPIO_PIN_RESET)` — 灭

就这么简单。第一课永远是 Blink（让 LED 闪烁），因为"看见了"比什么都重要。

## 三、中断：别让我一直盯着你

### 问题

你要检测一个按键有没有按下。最简单的做法是——主循环里反复读 GPIO，读到低电平就处理。这叫**轮询（Polling）**。

问题在哪？按键按下的瞬间只有几毫秒，你可能在干别的事而错过了。更糟的是，CPU 要一直循环检查，什么事也干不了。想同时干两件事（比如一边闪灯一边等按键），轮询就很难写。

### 中断怎么解决

中断就是——**硬件帮你盯着，有事了通知你。**

你把"按键按下时做什么"写好，注册成**中断服务函数（ISR）**。然后 CPU 该干什么干什么。按键按下→硬件检测到边沿→自动暂停当前程序→跳到你的 ISR 执行→执行完回到刚才断的地方。

整个过程像：你在看书，手机响了（中断信号），你放下书接电话（ISR），挂断后继续看书。

### 中断的铁律

1. **ISR 必须极短。** 你在 ISR 里延时 1 秒，外面的主循环就冻住 1 秒。正确做法是 ISR 里只置一个标志位，主循环看到标志位再处理。
2. **必须清除中断标志。** 硬件触发中断后会在寄存器里置一个标志位。你不清它就反复进 ISR，死循环。
3. **按键中断要消抖。** 机械按键按下时不是干净的"0→1"跳变，而是一串抖动脉冲（几毫秒内反复跳）。不做消抖，一次按触发几十次中断。硬件消抖（电容滤波）或软件消抖（检测到按下后等 20ms 再确认）都可以。

### 中断优先级

如果同时有两个中断来了（比如按键 + 定时器），先处理哪个？NVIC（嵌套向量中断控制器）按优先级排队。数字越小的优先级越高。高优先级的 ISR 可以打断低优先级的。

## 四、定时器与 PWM：让时间成为可控变量

### 定时器是什么

芯片内部有一个计数器，接到时钟源上，每个时钟周期加 1（或减 1）。你再设一个比较值，计到这里就触发事件。这个事件可以是：产生中断、翻转引脚电平、触发 ADC 采样...

**三个关键寄存器**：

| 寄存器 | 英文名 | 干什么的 |
|--------|--------|----------|
| 预分频器 | PSC | 把时钟频率降低。72MHz 的时钟 ÷72 = 1MHz，这样计数器每秒加 100 万次 |
| 自动重装载 | ARR | 计数器加到几就归零。ARR=999 时每 1000 个脉冲归零一次 |
| 计数器 | CNT | 当前计数值，一直在变 |

**定时周期公式**：`周期 = (PSC+1) × (ARR+1) / 时钟频率`

比如时钟 72MHz，PSC=71（分频后 1MHz），ARR=999，周期 = 72 × 1000 / 72000000 = 1ms。这就是个每 1ms 触发一次的定时器。

### PWM：用数字信号模拟模拟量

**PWM = Pulse Width Modulation，脉宽调制。**

你只能输出 0V 或 3.3V，不连续。但你快速地在 0 和 3.3V 之间切来切去，如果 50% 时间高电平、50% 时间低电平，整体效果约等于 1.65V。

怎么产生的？定时器工作在 PWM 模式：CNT 从 0 计到 ARR，当 CNT < 比较值(CCR)时输出高电平，CNT >= CCR 时输出低电平。

```
周期 = ARR + 1（以定时器计数单位算）
占空比 = CCR / (ARR + 1) × 100%
```

**三大应用**：

| 应用 | 频率 | 说明 |
|------|------|------|
| LED 调光 | 1-5 kHz | 占空比越大越亮 |
| 直流电机调速 | 10-20 kHz | 占空比大→转得快 |
| 舵机角度控制 | 50 Hz (20ms 周期) | 0.5ms 脉宽=0°，1.5ms=90°，2.5ms=180° |

**注意**：MCU 引脚不能直接驱动电机绕组。PWM 信号是控制信号，要通过 H 桥驱动芯片（如 TB6612、L298N）来放大电流，否则反电动势会把芯片烧掉。

## 五、ADC：感知模拟世界

### 为什么要 ADC

真实世界的物理量——温度、压力、电机角度（电位器）、光强——都是连续的模拟量。芯片只懂 0 和 1。需要一座桥把模拟变成数字。

**ADC = Analog-to-Digital Converter，模数转换器。**

原理：逐次逼近（SAR）最常用。拿参考电压（VREF）出来的电压和你输入的电压比，从高位到低位一位一位地试，最后得到一个数字值。

```
数字值 = (输入电压 / VREF) × (2^分辨率 - 1)
```

12 位 ADC，VREF=3.3V，输出范围 0~4095。输入 1.65V → 输出约 2047。

### 硬件要点

- **VREF 要稳。** VREF 决定你的"尺子"精度。VREF 不稳意味着尺子是橡皮筋。
- **AGND 和 DGND 要单点连接。** 模拟地和数字地不能随便混。数字电路噪声大，会通过地线耦合到模拟采样路径。只在一点连通两个地。

### 在电机控制里的角色

电机的角度和速度怎么知道？用**编码器**（Encoder）。编码器输出脉冲，通过定时器的编码器接口模式采集，得到位置和转速信息。但如果你用电位器来测角度，那就走 ADC 通道。

更常见的方式是编码器+定时器（不用 ADC），后面 PID 部分会讲。

## 六、串口通信（UART）：让芯片开口说话

### 为什么需要

你的代码跑在芯片上，怎么知道它跑对了？怎么看到变量的值？嵌入式没有屏幕，最简单的调试方式是——**让芯片把数据发到电脑上**。

UART 就是干这个的。两根线：TX(发) 和 RX(收)，全双工（可以同时收发）。

### 怎么工作

发送方以约定好的波特率（比如 115200 bps）一个 bit 一个 bit 地发出。接收方按同样波特率采样，还原出字节。

```
数据帧格式：[起始位0] [数据位8bit，LSB先] [校验位(可选)] [停止位1]
```

**双方必须严格匹配**：波特率、数据位(8)、停止位(1)、校验位(none)。这四个参数对不上就全是乱码。

### 电平标准

芯片输出的 UART 是 TTL 电平（3.3V/0V）。PC 的串口是 RS232 电平（±3~15V）。两者不兼容。你需要一个 **USB 转 TTL 模块**（CH340 芯片或 CP2102）来桥接。

连接：MCU_TX → USBTTL_RX, MCU_RX → USBTTL_TX, GND 必须共地。

### 调试流程

在代码里：`printf("speed=%d\r\n", current_speed);` 重定向到 UART → 串口助手（如 SSCOM、Putty）看到数据。这就是嵌入式最常用的调试手段。

## 七、PID 控制：让电机指哪打哪

### 问题

你已经会用 PWM 驱动电机了。给 50% 占空比，电机转起来，但不知道转多快，也不知道转了多远。

加上编码器读取位置和速度。现在你知道了当前状态和目标状态的差距。那怎么让电机**又快又稳又没有过冲**地到达目标？

开环不行（直接给固定 PWM 值不管结果），需要**闭环控制**。PID 就是最经典的闭环控制算法。

### PID 三个字母在干什么

把你的控制任务看成一个日常场景：**你在洗澡，调水温。**

水太冷，你拧向热水——**比例(P)**，偏差越大动作越大。

但拧到一半发现"好像还不够热"，你又拧了一点。这个"还不够"的感觉一直在积累——**积分(I)**，把历史的偏差累积起来，消除"就差一点点但永远到不了"的稳态误差。

水突然变烫了，你猛地往回拧——**微分(D)**，偏差的变化趋势，提前刹车防止超调。

PID 就是同时做这三件事：

```
输出 = Kp × 偏差 + Ki × 累计偏差 + Kd × (偏差变化率)
```

### 位置式 PID（控制位置/角度）

你要让电机转到 90°，编码器告诉你现在在 30°。

```
偏差 = 目标位置 - 当前位置
比例项 = Kp × 偏差
积分项 = Ki × 所有偏差的累加和
微分项 = Kd × (这次偏差 - 上次偏差)

PWM输出 = 比例项 + 积分项 + 微分项
```

位置式 PID 的输出直接对应 PWM 占空比，每一步都依赖所有历史偏差（积分项会一直累加）。这是**位置闭环控制**。

Kp、Ki、Kd 的物理含义：
- **Kp（比例）**：现在差 10°，我按 10 × Kp 的力推。Kp 大→响应快但容易震荡过冲。
- **Ki（积分）**：你已经差了 3 秒钟没到，我得加把劲。Ki 大→消除静差快但容易超调。
- **Kd（微分）**：你正在快速接近目标（偏差急剧减小），我得提前减力，不然会冲过头。Kd 大→抑制超调，但容易引入噪声放大。

### 增量式 PID（控制速度）

速度控制和位置控制不一样。速度控制通常只用 PI（没有 D 项），输出的是**控制量的增量**。

```
偏差 = 目标速度 - 当前速度
增量 = Kp × (偏差 - 上次偏差) + Ki × 偏差
输出 = 上次输出 + 增量
```

增量式 PID 的好处：**不用累加全部历史偏差**（只有相邻两次偏差的差值），计算量小，而且切换手动/自动时不会产生大的输出跳变（无冲击切换）。

### 速度怎么测（M 法测速）

编码器每转一圈产生固定数量的脉冲。用定时器开一个固定时间窗口（如 10ms），在这段时间里数脉冲个数。

```
速度（转/分钟） = 脉冲数 / 每圈脉冲数 / 时间窗口(分钟)
```

比如：编码器 1000 线/圈，10ms 内数到 50 个脉冲 → 50 / 1000 / (0.01/60) = 300 转/分。

### 参数整定（三个旋钮怎么调）

经典试凑法：

1. Ki=0, Kd=0, 从小往大调 Kp，直到系统出现等幅振荡。此时记下 Kp = Ku（临界比例）。
2. 加入 Ki，从非常小开始，Kp 适当减小。消除稳定时残留的小偏差（静差）。
3. 加入 Kd（如果需要），从很小开始，抑制超调和振荡。

口诀：**Kp 定响应速度，Ki 消静差，Kd 压超调。**

### 一个完整的速度闭环控制流程

```
while(1) {
    1. 读编码器 → 算当前速度
    2. 偏差 = 目标速度 - 当前速度
    3. PID计算 → 得到 PWM 增量
    4. 更新 PWM 占空比 → 输出给电机驱动
    5. 等待定时周期（如 10ms）
}
```

放在定时器中断里执行，保证控制周期严格固定（比如固定 10ms 算一次 PID）。

## 八、嵌入式学习路线图

### 你需要的技能栈（按优先级）

```
第一层：看懂硬件怎么接线
  GPIO 输入输出 → 会用万用表 → 看懂原理图（引脚连到哪）

第二层：理解芯片怎么工作
  时钟树 → 中断 → 定时器 → PWM → ADC → UART 调试

第三层：让电机听话
  编码器读取 → PID 原理与代码 → 速度环 → 位置环 → 参数整定

第四层（可选加分项）：
  I²C/SPI 总线 → RTOS 多任务 → 电源/低功耗 → DMA
```

### 对你面试最重要的是什么

1. **能把 PID 的三个参数讲清楚** — 不只是背公式，能说出什么时候该加 Kp、什么时候该加 Ki、Kd 为什么容易引入噪声
2. **知道 PWM+编码器+PID 怎么组成闭环** — 画出数据流: 目标 → 偏差 → PID → PWM → 电机 → 编码器 → 反馈回来
3. **有一些动手经验可以聊** — 哪怕只是"我用 STM32 做过一个速度环控制"
4. **理解嵌入式的基本约束** — 实时性、资源紧张、ISR 必须短、没有 printf 时怎么调试
